# Migration notes: 20260911041711_data_foundation

Applies the Phase 2 data-foundation schema (`docs/adr/` ADR-001…004). Hand-written,
non-destructive, single transaction.

## What it does, in order

1. Creates the enums: `SourceType`, `TrustClass`, `RedistributionReviewStatus`,
   `PriceType`, `ReferencePriceType`, `ObservationStatus`.
2. Creates `DataSource` and inserts the 4 seed rows
   (`extension:content-script`, `bestbuy:products-api`, `manual`,
   `synthetic:test`) with `ON CONFLICT (key) DO NOTHING`. **These rows are
   duplicated in `DATA_SOURCE_DEFINITIONS` (`@pricetruth/shared`) and
   `seed.ts`** — migrations cannot import TS; keep the lists in sync when adding
   a source.
3. Creates `ListingVariant` (`@@unique([listingId, fingerprint])`) and
   `ObservationStatusEvent` (FK wired after the fact rebuild).
4. Casts entity ids `TEXT → uuid` (`USING "id"::uuid`) — a loud cast: any
   invalid value aborts the transaction rather than being coerced.
5. Rebuilds `PriceObservation`:
   - Guard `DO` block: raises if any old row still carries variant JSON
     (`variant IS NOT NULL AND variant <> 'null'::jsonb`). MVP rows never did;
     the app-side fingerprint (sha256 of canonical sorted-keys JSON) cannot be
     reproduced from the stored JSON text, so refusing is safer than guessing.
   - `PriceObservation_new` created with `BIGINT GENERATED BY DEFAULT AS
IDENTITY` pk, `Uuid` FKs, and the new column set.
   - `INSERT … SELECT` ordered by `(observedAt, receivedAt)` so new ids are
     ascending in observed-time order, with mappings:

     | Old column                              | New column(s)                                                                                                                       |
     | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
     | `id` (text uuid)                        | — (replaced by bigint sequence)                                                                                                     |
     | `listingId`                             | `listingId::uuid`                                                                                                                   |
     | `source` (text key)                     | `dataSourceId` via `DataSource` join on `key` (inner join — unknown source fails the count guard below)                             |
     | `observedAt`                            | `clientObservedAt`                                                                                                                  |
     | `receivedAt`                            | `receivedAt`; also `effectiveAt` when source is CLIENT_REPORTED                                                                     |
     | `observedAt`                            | `effectiveAt` when source is SERVER_FETCHED/VERIFIED/TEST                                                                           |
     | `observedAt − receivedAt`               | `clientSkewSeconds` (CLIENT_REPORTED only; null otherwise)                                                                          |
     | —                                       | `priceType = 'STANDARD'`, `referenceType = 'UNKNOWN'` iff `referencePriceCents` present, `schemaVersion = 1`, `status = 'ACCEPTED'` |
     | `variant`, `userAgentHash`, `ingestKey` | dropped (variant → `ListingVariant`; the others removed by design)                                                                  |

   - Guard `DO` block: raises if `old count <> new count` (catches unknown
     `source` keys or failed uuid casts slipping through).
   - Renames `_new` into place, drops the old table, re-attaches indexes/FKs
     with Prisma-convention names.
6. CHECK constraints not expressible in Prisma: `priceCents > 0`,
   `referencePriceCents > 0`, reference-type consistency
   (`referencePriceCents IS NULL` ⇔ `referenceType IS NULL`),
   `currency ~ '^[A-Z]{3}$'`, `schemaVersion >= 1`, non-empty
   `externalId`/`DataSource.key`.
7. `pricetruth_forbid_observation_mutation()` trigger on `PriceObservation`:
   rejects all DELETEs and any UPDATE touching a column other than `status`
   (see ADR-001).

## How to run

- Fresh database: `DATABASE_URL=… pnpm exec prisma migrate deploy` (applies
  `init` then this migration).
- Upgrade an MVP database: same command. Preconditions:
  - Postgres reachable at `DATABASE_URL` with rights to alter the schema.
  - All entity `id`/`listingId` values are valid uuids (true for all
    app-written rows).
  - Every `PriceObservation.source` matches a `DataSource.key`
    (`extension:content-script`, `bestbuy:products-api`, `manual`,
    `synthetic:test`) — unknown sources abort via the count guard.
  - No `PriceObservation.variant` JSON (guard raises; handle manually first).

## Rollback

There is no down migration. Restore from a pre-migration backup/dump. The
migration is transactional, so a failure leaves the database untouched.

## How it was tested

`apps/api/test/migration.test.ts` runs both paths against a scratch database
(`pricetruth_migration_test`, created and dropped by the test):

- **Path A** — empty DB, `migrate deploy`, then
  `migrate diff --from-url … --to-schema-datamodel … --script` must produce no
  Prisma-managed drift (the diff is empty; the trigger and CHECK constraints
  are not representable in the datamodel and are not emitted as drops in this
  direction).
- **Path B** — applies only `init`'s SQL via `prisma db execute`, marks it
  applied via `migrate resolve`, inserts a deterministic MVP-shaped sample (2
  retailers, 3 listings incl. bestbuy `10129617`, 12 observations across 6 days
  from `extension:content-script` and `bestbuy:products-api`), runs
  `migrate deploy`, then asserts: count unchanged (12→12), listing uuids
  preserved verbatim, observation ids ascending bigint in chronological order,
  `dataSourceId` resolved on every row, `effectiveAt = receivedAt` for
  CLIENT_REPORTED rows and `= clientObservedAt` for SERVER_FETCHED rows,
  `referenceType = 'UNKNOWN'` iff a reference price is present. It then serves
  `GET /v1/listings/bestbuy/10129617/analysis` from the migrated DB: 200,
  `currentPriceCents` 23899, `referencePriceCents` 27499, 4 observations —
  INSUFFICIENT confidence with `advertisedDiscountPct` 13.1. Full output:
  `~/phase2-migration-evidence.txt` (kept outside the repo).
